## 全体像

このノートで扱う範囲はここです。

```
あなたのPC（Windows / Mac）
  │
  └─ 仮想マシン（VM）
       │
       └─ Ubuntu Server
            │
            └─ ★Docker ← このノートのテーマ
                 │
                 ├─ コンテナA（アプリ本体）
                 ├─ コンテナB（データベース）
                 └─ コンテナC（キャッシュ）
```

Dockerは複数のコンテナをまとめて管理する仕組みです。アプリを複数の「箱」に分けて動かすのが特徴です。

---

## 本編

### 1. Dockerは「アプリ専用のお弁当箱」

Dockerとは、アプリとその動作に必要なすべてのもの（設定・ライブラリ・依存ファイルなど）を1つの「箱」にまとめて動かす仕組みです。この箱を**コンテナ**と呼びます。

お弁当箱で例えると、「ご飯・おかず・お箸・ソース、全部が1つのお弁当箱に入っていて、どこに持って行っても同じ状態で食べられる」イメージです。アプリが「どのPC・どのOSでも同じように動く」のがDockerの最大のメリットです。「自分のPCでは動いたのに、他の環境では動かない」という問題を解消します。

---

### 2. コンテナとVMは何が違うのか

似たような仕組みに聞こえますが、VMとDockerは目的が違います。

```
VM     ── 「PC全体」を仮想化する。OSも含めてまるごと再現する。
コンテナ ── 「アプリ単体」を分離する。OSはホスト（Ubuntu Server）を共有する。
```

「建物を丸ごと建てる」のがVMで、「建物の中の一部屋だけ用意する」のがコンテナです。コンテナの方が軽くて速く起動できますが、OS自体はホストのものを使います。だからこのシリーズでは「VMの中でDockerを動かす」という構成にしています。VMで本番PCを守り、Dockerでアプリを管理する、という役割分担です。

---

### 3. イメージ・コンテナ・ボリュームの3つを覚えよう

Dockerで最初に出てくる3つの概念を整理します。

```
イメージ  ── アプリの「設計図」または「冷凍食品のパッケージ」
            （Docker Hubというサービスからダウンロードできる）

コンテナ  ── そのイメージを実際に動かした「実体」
            （冷凍食品を電子レンジで加熱した「完成品」）

ボリューム ── コンテナの外にデータを保存する仕組み
            （写真や設定などの大切なデータを、コンテナが消えても残す）
```

ボリュームが特に重要です。コンテナは「壊れたら作り直す」使い捨ての発想で設計されています。だからこそ、失いたくないデータはコンテナの外（ボリューム）に置く必要があります。

---

### 4. docker-composeは「複数コンテナの指揮者」

本格的なアプリは、1つのコンテナだけで動くことはほとんどありません。アプリ本体・データベース・キャッシュなど、複数のコンテナが連携して動いています。

それぞれを手動で1つずつ起動するのは大変なので、**docker-compose**という仕組みがあります。`docker-compose.yml`という1つの設定ファイルに「どのコンテナを・どんな設定で・どう連携させるか」を書いておくと、コマンド1つで全コンテナが一斉に起動できます。楽団の**指揮者**が全員を同時に動かすイメージです。

---

### 5. 初心者が詰まりやすいポイント分類

Dockerを始めるときによく起こる詰まりを、あらかじめ分類しておきます。具体的な対処方法は有料ノートで扱いますが、「どこで詰まるか」を知っておくと心の準備になります。

```
【概念系の詰まり】
  ・イメージとコンテナの区別が混乱する
  ・「コンテナを消してもデータは残る」仕組みが腹落ちしない

【インストール系の詰まり】
  ・権限エラー（sudo が必要な操作を見落とす）
  ・インターネットに繋がっていないVMで試してしまう

【起動系の詰まり】
  ・コンテナが起動してもすぐ終了する（設定ファイルのミス）
  ・ブラウザからアクセスできない（ポートやIP設定の問題）
```

有料ノートP02・P03では、これらの詰まりに対応する地雷マップと復旧ルートを用意しています。

## よくある詰まりと対処

> ※ 無料ノートでは「詰まりの原因カテゴリ」をお伝えします。

**「VMとDockerの違いがまだぼんやりしている」系**
→ 「建物（VM）の中の一部屋（コンテナ）」という例えをもう一度読んでみてください。実際に使い始めると体感でわかってきます。

**「ボリュームがなぜ必要かピンとこない」系**
→ 「コンテナは壊れたら作り直す使い捨て前提」という発想を先に受け入れると腹落ちします。大切なデータを外に出しておく＝保険をかける、というイメージです。

**「docker-composeのファイルを読めそうにない」系**
→ 有料ノートP03では「読むべき箇所」と「触らなくていい箇所」を明示します。全部理解しなくても動かせます。

## 用語集

| 用語 | かんたん説明 |
|------|-------------|
| Docker | アプリをコンテナに入れて動かす仕組み |
| コンテナ | アプリとその必要物をまとめた「箱」。使い捨て前提 |
| イメージ | コンテナの設計図・冷凍食品パッケージに相当 |
| ボリューム | コンテナの外にデータを保存する仕組み。コンテナ削除後もデータが残る |
| docker-compose | 複数コンテナをまとめて起動・管理する仕組み |
| docker-compose.yml | docker-composeの設定を書くファイル |
| Docker Hub | Dockerイメージを配布している公式サービス |
| ライブラリ | アプリが動くために必要な補助プログラム・部品 |
| 依存関係 | アプリが動くために必要な他ソフトウェアとの関係 |
